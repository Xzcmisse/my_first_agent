# RAG 检索增强生成知识库

## 1. RAG 是什么
- RAG 是 Retrieval-Augmented Generation 的缩写，中文叫检索增强生成。它先从外部知识库检索相关资料，再把资料和问题一起交给大模型生成答案。
- RAG 可以理解为开卷考试：模型参数不变，答案依据来自外部资料；知识更新时重新整理资料和索引即可。
- 微调可以理解为闭卷考试：知识被写进模型参数，更新知识通常需要重新训练或继续训练。
- 一个完整的 RAG 系统包含检索和生成两个阶段。检索负责找到相关资料，生成负责根据资料组织答案。
- RAG 的目标不是让模型记住全部知识，而是在回答当前问题时提供正确、可控、可追溯的上下文。

## 2. 离线建库与在线查询
- 离线建库是在用户提问前完成的工作，通常依次包括读取文档、清洗文本、切块、向量化和建立索引。
- 在线查询是在用户提问时完成的工作，通常包括把问题向量化、检索 top-k、取回原文、拼接提示词和调用生成模型。
- 把建库和查询拆开，可以避免每次提问都重新读取和编码全部文档，从而降低延迟和计算成本。
- 离线建库的输出通常包括向量索引和原文元数据。两者必须来自同一次建库，并且一起更新。
- 索引负责保存向量和相似度检索结构；元数据负责保存每个块的原文、来源、章节和版本。
- 如果只保存 FAISS 索引，系统只能得到相似向量的编号，无法知道编号对应什么文字。
- 如果只保存原文元数据，系统没有向量索引，无法进行向量相似度搜索。
- 文档、模型或切块参数发生变化时，应重新建库并重新生成配套的索引和元数据。

## 3. 文档切块 Chunking
- chunk 是文档被切分后得到的文本块。一个块通常承载一个相对完整的语义单元。
- 文档太长时，如果整篇只生成一个向量，多个主题会被平均到一个表示中，检索信号会变弱。
- 块太短会缺少上下文，块太长会混入多个主题。切块需要在信息完整和检索精度之间做平衡。
- max_len 表示单个块允许的最大字符数或 token 数。
- overlap 表示相邻块之间保留多少重叠内容，用来减少句子被切断造成的语义损失。
- min_len 表示最小块长度，过短的符号、目录碎片和空内容通常会被过滤。
- 按行切块适合结构简单、每行只表达一个知识点的资料；不适合一句话跨越多行或段落语义强耦合的资料。
- 把章节标题拼到块前面，可以帮助检索器知道这个块属于哪个主题。
- 标题前缀也有风险：同一个小节下的很多块会共享相同前缀，可能互相抢占检索排名。
- 如果长块被切分成多段，每一段都应保留必要的标题或来源信息，避免后续段落失去上下文。
- 每个块建议保存至少三个字段：文本内容、来源文档和章节标题。生产环境还可以增加文档编号、版本和更新时间。

## 4. Embedding 与相似度
- embedding 是把文本映射成一组数字向量。向量的每一维不是一个可以直接解释的单词，而是模型学到的语义特征。
- bge-small-zh-v1.5 在本项目中输出 512 维向量，因此每个块对应 512 个浮点数。
- 文档块和用户问题必须使用同一个 embedding 模型，否则它们位于不同的向量空间，相似度没有意义。
- 向量归一化后，内积相似度等价于余弦相似度。归一化可以降低文本长度对分数的影响。
- 相似度分数只表示两个向量在模型空间中的接近程度，不是答案正确的概率，也不能直接解释为百分比。
- 不同 embedding 模型产生的分数不能直接横向比较；更换模型后需要重新建立索引并重新评估。
- 向量检索擅长发现语义相近的表达，但不擅长解释逻辑关系，也不会判断一段文字是在提出问题还是在回答问题。

## 5. FAISS 与索引
- FAISS 是向量检索库，负责高效计算查询向量与已有向量的相似度，并返回最相近的编号。
- FAISS 不是完整的向量数据库。它本身不负责文档管理、权限控制、版本管理、事务和复杂的元数据过滤。
- IndexFlatIP 是一种平铺索引，使用内积作为相似度度量。数据量不大时，它会逐个比较查询向量和所有库中向量。
- 本项目中向量已经归一化，所以 IndexFlatIP 的内积结果可以当作余弦相似度使用。
- 向量的加入顺序会形成编号。第 0 行向量对应元数据列表中的第 0 个块，第 1 行对应第 1 个块，依此类推。
- 检索返回的是分数和编号，不是原文。系统必须用编号回到元数据中取回文本和来源。
- 当文档规模变大时，可以使用更高效的索引结构，但需要接受一定的召回率、内存和构建时间权衡。

## 6. 检索策略与 top-k
- top-k 表示一次检索返回最相似的前 k 个结果。k 越大，召回正确答案的机会通常越高，但上下文噪声和成本也会增加。
- 命中@1 表示正确内容是否出现在第一条结果中；命中@3 表示正确内容是否出现在前三条结果中。
- top-k 是一个硬截断。如果正确答案排在第四名，而系统只取前三名，后续生成模型就看不到它。
- 查询改写可以缓解用户表达和文档表达不一致的问题。例如文档写 lr，用户问学习率，可以在查询中补充 lr 这个同义表达。
- 词表鸿沟是指问题和文档表达同一个概念时使用了不同词语，导致向量模型或关键词检索无法可靠匹配。
- BM25 擅长精确关键词匹配，向量检索擅长语义相似。混合检索可以同时利用两路结果。
- 混合检索通常需要融合两路分数，常见做法包括加权求和、倒数排名融合和合并后重排。
- reranker 是重排模型。它会对初步召回的候选块做更精细的相关性判断，把真正能回答问题的块排在前面。
- 只提高 k 不能解决所有问题。更重要的是先保证知识库干净，再考虑查询改写、混合检索和重排。
- 检索结果还应做去重和来源过滤，避免同一段话被重复切块后占满多个 top-k 位置。

## 7. Prompt 与生成
- 生成阶段要把用户问题和检索到的资料一起放进提示词，让模型基于上下文回答。
- 提示词应明确要求模型只使用给定资料，不要补充资料中没有的事实。
- 提示词应要求模型在资料不足时明确说明无法回答，而不是猜测。
- 提示词应要求模型标注引用来源，方便人工核查答案是否来自知识库。
- 如果资料中包含公式或定义，应要求模型原样引用，不要自行推导资料之外的公式。
- temperature 控制采样随机性。设置为 0 可以让输出更稳定，但不会消除知识缺失、检索错误和模型幻觉。
- 小模型即使拿到了正确资料，也可能不会抽取、概括或遵守指令。此时要同时检查提示词和模型能力。
- 检索正确不等于回答正确。生成模型仍可能忽略资料、混入旧知识或补写不存在的细节。
- RAG 不能保证答案一定正确，它提供的是一个可以检查证据链的问答框架。

## 8. 评估与数据质量
- 评估检索质量需要固定的测试问题、标准答案和正确来源，不能只凭一次问答感觉判断。
- 测试问题应尽量改写，不要直接复制知识库原句，否则容易因为字面重合而得到虚高分。
- 评测污染是指测试问题、标准答案或评测表格本身进入了知识库，系统检索到的只是题目而不是答案。
- 小样本结果波动很大。几条题的命中率不能代表整体质量，建议至少准备二十到三十条覆盖不同主题的题。
- 每次对比只改变一个变量，例如只换切块参数、只换 embedding 模型或只换生成模型，才能判断变化来自哪里。
- 评估应同时看检索指标和生成指标。检索指标回答有没有找到资料，生成指标回答有没有忠实使用资料。
- 生成评估应检查答案正确性、来源一致性、是否遗漏关键信息以及是否出现资料外的内容。
- 个人笔记适合记录踩坑和思考，正式知识库适合保存稳定、可复用、无评测污染的知识条目。

## 9. 生产环境检查清单
- 每篇文档应有唯一编号、标题、版本、更新时间和负责人，便于追踪和增量更新。
- 知识库应支持新增、修改和删除文档。删除文档后，对应的索引和元数据也要同步清理。
- 应区分正式知识、个人笔记、测试数据和评测题目，避免测试内容进入生产索引。
- 应控制访问权限，敏感数据不能进入无权限隔离的公共索引。
- 应记录检索日志、命中的来源和最终答案，方便排查错误和做质量分析。
- 应设置知识过期和一致性检查，避免过期文档长期影响答案。
- 应建立固定评测集，在切块、模型、提示词或索引升级后进行回归测试。

## 10. 常见误区
- 误区一：RAG 就是微调。实际上 RAG 主要改变外部上下文，微调主要改变模型参数。
- 误区二：FAISS 就是向量数据库。FAISS 是检索库，完整的数据库还需要存储、元数据、权限和运维能力。
- 误区三：embedding 就是答案。embedding 只是语义向量，答案仍需要检索和生成。
- 误区四：相似度分数越高，答案一定越正确。分数只表示向量接近程度，不保证内容能回答问题。
- 误区五：检索到资料就等于回答正确。生成模型可能误读、忽略或补写资料外的内容。
- 误区六：知识库越乱，换个更大的模型就能解决。脏数据和不合适的切块会先破坏检索，模型无法凭空恢复缺失上下文。
- 误区七：提示词可以解决所有问题。提示词只能约束生成行为，不能修复检索错误和知识缺失。
